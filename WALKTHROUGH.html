Episode 3 · Python + Lumen AI Chat

Reviewer Agent: build guide

A study reviewer that answers only from your notes, names its sources, and quizzes you. It runs on Lumen AI Chat: plain Python picks the parts of your notes that match each question and sends them with it, refuses any answer without a real source, and turns Lumen's quiz into something Python can check and grade. Track A sets up Lumen AI Chat and runs the finished Final. Track B builds the same agent from the Demo template, one TODO at a time. Start with How it works for an interactive map of the whole system. Commands are for Windows PowerShell.

    A3 to A5 · the instances and the key

    An instance is one assistant on Lumen AI Chat. Your code sends the notes and the rules with every message, so an instance needs only a persona that expects them. The API can list instances but can't create or edit them, so this part happens in the Organization Portal. The API reference is at sandbox.docs.lumensuite.io.

    A3

    Set up the three instances

    Organization Portal · Lumen Assistant
    1. In Lumen Assistant, click Create Instance three times: Bio, Econ and PH History. (Already made? Use each one's ⋮ → Edit persona.)
    2. Give all three the same Persona, from instance_rules.md:
    You are a study reviewer for students. Each message contains excerpts from the student's own study notes, labeled with the file name and page, followed by a question or a request for a practice quiz. Answer only from the notes in the message, and follow the format the message asks for.
    1. Set the Out-of-scope Reply to Not in your notes. and click Save Changes.

    Why the persona matters: every message passes the instance's scope check first, and the check compares it with the persona. A narrow persona like "a Reviewer Agent for Biology" blocks the messages that carry notes and instructions; they come back as the out-of-scope reply.

    Phase 1 · Ask · TODO 1 to 4 · 01_ask.py

    Your own Lumen client, and the guard. Every call ends with expect(r, status) from helpers.py: it returns the JSON body, or raises one clear sentence naming the Lumen error and its fix.

    TODO 1

    The two headers

    01_ask.py → lumen_headers, replace the raise line
    return {"lumen-api-key": LUMEN_API_KEY, "lumen-api-secret": LUMEN_API_SECRET}

    Lumen has no login and no token: these two headers go on every call. config.py reads both from .env.

    TODO 2

    Open a session

    01_ask.py → open_session, replace the raise line
    r = http.post(f"{AI_CHAT}/instances/{instance_id}/sessions",
              headers=lumen_headers(), json={"title": title})
body = expect(r, 201)
return body["Session"]["id"]

    A new session answers 201 (created), not 200. Keep Session.id: every question in this conversation goes to it. 2 credits.

    TODO 3

    Send a question

    01_ask.py → send_message, replace the raise line
    r = http.post(f"{AI_CHAT}/instances/{instance_id}/sessions/{session_id}/messages",
              headers=lumen_headers(), json={"message": question})
a = expect(r, 200)["Answer"]
return NotesAnswer(
    text=a.get("answer") or "",
    sources=[Source(title=c) for c in a.get("citations") or []],
    degraded=a.get("degradedSources") or [],
)

    The call that runs Lumen's model: a few seconds and 5 credits. The body key is message, not question.

    TODO 4

    No source, no answer

    01_ask.py → answer_or_refuse, at the top
    if not a.sources or a.text.strip().startswith("Not in your notes"):
    return f"⚠️ Not in your {subject} notes. No guess."

    The second layer: the rules in the message ask Lumen to refuse; this refuses anyway when no real source comes back. A source counts only if it names a page the message really sent (named_sources() in notes.py). LumenNotes (given, below your TODOs) opens the session on the first question, reuses it, and retries once when that helps.

    python 01_ask.py "Ano ang ATP?"
python 01_ask.py "Sino si Rizal?"
python check.py 1

    ✓ The first prints a 📎 source, the second ⚠️ Not in your bio notes. No guess., and check.py 1 ends with ✅ phase 1 of 3 passes.

    Phase 2 · Quiz · TODO 1 to 3 · 02_quiz.py

    Lumen writes the quiz; Python checks it and grades it. Lumen replies in plain text with no forced shape, so QUIZ_PROMPT (given) asks for JSON, and Python does the strict part.

    TODO 1

    The Quiz form

    02_quiz.py → class Question, between c and why
    answer: Literal["a", "b", "c"]
source: str = Field(description="The note and page the answer comes from")

    Literal["a", "b", "c"] means the answer can only be one of those three letters. A given validator lowercases "A" first.

    TODO 2

    Parse Lumen's reply

    02_quiz.py → parse_quiz, replace the raise line
    return Quiz.model_validate_json(extract_json(reply))

    extract_json() cuts out the {...}, even with "Here is your quiz:" or ```json fences around it. model_validate_json() checks every field. If it doesn't fit, write_quiz() asks Lumen once more (5 credits).

    TODO 3

    Python grades

    02_quiz.py → is_correct, replace the raise line
    return letter.strip().lower() == q.answer

python check.py 2

    ✓ Five questions, one at a time, each with ✅ Tama! or ❌ The answer is ..., the reason and the source. One row is added to quiz_log.csv. check.py 2 ends with ✅ phase 2 of 3 passes.

    If something goes wrong

    You seeFix
    running scripts is disabledSet-ExecutionPolicy -Scope CurrentUser RemoteSigned, then activate again.
    No .env yetcopy .env.example .env, then paste what the host sent you.
    paste the instance IDs from the host in .env; missing: ...Paste the IDs. python reviewer.py instances lists them (1 credit).
    this key sees no AI Chat instances yetCreate the instances in the Organization Portal (A3), in the same organization as the key.
    not in this key's instances: bioA typo in that instance ID. Copy it again.
    Lumen said 401 API_KEY_NOT_FOUND (or API_SECRET_NOT_FOUND)A typo, or the key and secret are swapped. Copy both again.
    Lumen said 403 ACCESS_DENIEDThe key has no AI Chat grant. Students: tell the host. Host: add it in the Organization Portal, under Settings → API Keys.
    Lumen said 403 API_CREDITS_INSUFFICIENT or LC_INSUFFICIENTThe key's API credits, or the organization's Lumen Credits, ran out. LC_INSUFFICIENT stops everyone.
    Lumen said 503 FEATURE_DISABLEDAI Chat is off on that gateway. Use the staging LUMEN_BASE_URL from .env.example.
    Lumen said 400 AI_CHAT_QUERY_TOO_LONGThe message went over 2,000 characters. Keep questions short; don't change MAX_MESSAGE in notes.py.
    Lumen said 504 AI_CHAT_REPLY_TIMEOUTOver 25 seconds, not charged. Try again, or keep each instance to one subject.
    wrong path: ...A typo in a URL f-string (TODO 2 or 3). Compare it character by character.
    send json={"message": question}The body key must be message.
    Every answer is ⚠️ Not in your ... notesNo Source: line came back, or the instance answered "out of scope". Check TODO 3 returns a.get("answer"); if it does, set the instance persona from A3.
    answer should be Literal["a", "b", "c"]A typo in TODO 1 of Phase 2. Keep the quotes around each letter.
    Lumen's quiz failed the check twiceRun it again. If it repeats, check the instance persona (A3).
    python app.py says the address is in useAnother copy is running. Close it, or run $env:REVIEWER_PORT="8767"; python app.py.
    Emoji show as ?Run chcp 65001 first, or use Windows Terminal.
    check.py says TODONot an error: that part isn't written yet. The message names the TODO.
